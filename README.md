# Test Blueprint Builder

![LaTeX](https://img.shields.io/badge/export-LaTeX%20%7C%20Excel%20%7C%20Markdown-008080?style=flat-square&logo=latex&logoColor=white)
![License: MIT](https://img.shields.io/badge/license-MIT-green?style=flat-square)

> Plan balanced exams from a reference framework — and check whether the exam
> you actually assembled still matches the plan.

A **test blueprint** (table of specifications) states how many items an exam
must have in each content domain, competency and cognitive level. It is the
backbone of content validity: without it, exams drift toward whatever topics
item writers find easiest to write about. This tool turns a small YAML
framework into an exact, reproducible item allocation and exports it in the
formats a committee actually uses.

## ✨ Features

- **Exact integer allocation** with the largest-remainder (Hamilton) method, applied
  hierarchically: domain → competency → cognitive level. Totals always add up.
- **Minimum items per domain** (floors) for short exams, re-apportioning the rest.
- **Exports:** Markdown, Excel (summary + cells + domain × competency), CSV and a
  print-ready **LaTeX/PDF** blueprint.
- **Alignment check** of a finished exam against the blueprint per dimension:
  planned vs actual counts, **Porter's alignment index** and a **χ² goodness-of-fit** test.

## 🚀 Quick start

```bash
git clone https://github.com/alencarpeixotofilho-cloud/test-blueprint-builder.git
cd test-blueprint-builder
pip install -e .

python -m blueprint build --framework examples/framework.yaml --out out/
python -m blueprint build --framework examples/framework.yaml --items 40 --out out40/
python -m blueprint check --framework examples/framework.yaml --exam examples/exam_items.csv
```

### The framework file

```yaml
name: Sample Clinical Sciences Framework
items: 100
domains:
  Internal Medicine:
    weight: 25
    min_items: 15          # floor, only binds on short exams
    competencies: {Diagnosis: 40, Management: 40, Prevention: 20}
  Surgery:
    weight: 20
    competencies: {Diagnosis: 35, Management: 50, Prevention: 15}
  # ...
cognitive_levels: {Recall: 20, Application: 50, Analysis: 30}
```

Weights are relative and normalized automatically. See the full example in
[`examples/framework.yaml`](examples/framework.yaml).

## 📊 Example output

**100-item exam** (`build`):

| Domain | Recall | Application | Analysis | Total |
|---|---:|---:|---:|---:|
| Internal Medicine | 5 | 13 | 7 | 25 |
| Obstetrics & Gynecology | 4 | 11 | 5 | 20 |
| Pediatrics | 3 | 11 | 6 | 20 |
| Public Health | 3 | 8 | 4 | 15 |
| Surgery | 4 | 10 | 6 | 20 |
| **Total** | **19** | **53** | **28** | **100** |

With `--items 40` the Internal Medicine floor kicks in (15 items instead of 10)
and the other domains are re-apportioned.

**Alignment check** of an assembled exam (`check`):

```text
== domain ==      alignment index = 0.930   chi2(4) = 2.59,  p = 0.629   ✔ acceptable
== competency ==  alignment index = 0.860   chi2(4) = 11.57, p = 0.021   ⚠ drift
== level ==       alignment index = 0.840   chi2(2) = 16.75, p < 0.001   ✖ too much recall
```

Generated files for the example are in [`docs/sample/`](docs/sample/), including
the PDF blueprint ([`blueprint.pdf`](docs/sample/blueprint.pdf)).

## 🧮 Methods

* **Hamilton apportionment.** Each unit is first assigned by the integer part of
  its quota; leftover units go to the largest fractional remainders. Every cell
  is within one item of its exact quota at its level of the hierarchy.
* **Floors.** If a domain's proportional share is below its `min_items`, it is
  fixed at the floor and the remainder is re-apportioned among the others
  (iterated until stable).
* **Hierarchical rounding.** Because rounding happens inside each parent cell,
  column totals (e.g. total *Recall* items) can differ by ±1 from the global
  target — a deliberate trade-off that keeps every domain total exact.
* **Alignment index** (Porter, 2002): `1 − ½ Σ |p_planned − p_actual|`,
  ranging from 0 (no overlap) to 1 (identical distributions).

├── blueprint/

## 🔒 Data & privacy

Everything here is fictitious: the framework is a generic clinical-sciences
example and the assembled exam is randomly generated by
[`examples/make_sample_exam.py`](examples/make_sample_exam.py). No real exam
content is included.
